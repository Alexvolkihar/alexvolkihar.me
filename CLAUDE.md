# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal website/blog (fork of antfu.me), built with Vue 3 + Vite + Vite-SSG as a fully static site. Content lives as Markdown files that are auto-routed; there is no backend/API — everything ships as static HTML/JS at build time.

## Commands

```bash
pnpm install       # install deps (pnpm@11.5.0, workspace catalogs in pnpm-workspace.yaml)
pnpm dev           # start dev server on :3333
pnpm build         # full production build: static assets + vite-ssg build + fonts + rss + redirects
pnpm preview       # preview the production build locally
pnpm lint          # eslint .
pnpm static        # refresh temp/ from antfu/static (degit) + copy sponsor assets
```

There is no test suite/runner configured in this repo — do not invent test commands.

`pnpm lint` is also run automatically on staged files via a pre-commit hook (`simple-git-hooks` + `lint-staged`), so linting issues on touched files will block commits.

## Architecture

### Routing & content pipeline

- Routes are auto-generated from the `pages/` directory via `vue-router/vite` (configured in `vite.config.ts`) — both `.vue` and `.md` files become routes, there is no manual route table.
- `pages/posts/*.md` are blog posts; `lang: 'en'` frontmatter posts are included in the RSS/Atom/JSON feeds generated by `scripts/rss.ts`.
- Every `.md` page frontmatter (title, date, lang, image, tags, etc.) is read via `gray-matter` in `vite.config.ts`'s `extendRoute` and injected into the route's `meta.frontmatter`.
- Markdown → Vue compilation goes through `unplugin-vue-markdown`, wrapped in `WrapperDemo` (for pages under `demo/`) or `WrapperPost` (everything else) — see `src/components/WrapperDemo.vue` / `WrapperPost.vue`.
- The markdown pipeline (`markdownItSetup` in `vite.config.ts`) wires up Shiki syntax highlighting (dual `vitesse-dark`/`vitesse-light` themes, twoslash, diff/highlight notations), heading anchors, table of contents, GitHub-style alerts, auto-linking of known project names, and a custom `fence` renderer that turns ` ```mermaid ` code blocks into `<Mermaid :code="..." />` components (rendered client-side to avoid SSR issues — see `src/components/Mermaid.vue`).
- OG images: if a page has no explicit `image` in frontmatter, `frontmatterPreprocess` either copies a same-named `.png` sitting next to the `.md` file, or generates one from the title via `scripts/og-template.svg` + `sharp` into `public/og/<route>.png`. Generation promises are collected and awaited in the `closeBundle` Vite plugin hook at the end of `vite.config.ts` — don't assume OG images exist synchronously during the plugin pipeline.

### Client app

- `src/main.ts` is the sole entry point: sets up `ViteSSG(App, { routes }, ...)`, installs Pinia, FloatingVue, dayjs locale plugin, NProgress route-transition indicators, and `vue-router-better-scroller` for scroll restoration (with sliding-transition CSS toggled based on scroll direction).
- `src/store/shiki.ts` (Pinia) owns the client-side Shiki highlighter instance and current theme — used for syntax highlighting interactions that need to happen post-hydration.
- `src/logics/index.ts` holds shared UI utilities (dark mode toggling, date formatting, gallery view state, local preferences).
- Path alias `~/*` maps to `src/*` (see `tsconfig.json` / `vite.config.ts`).
- Auto-import is enabled for Vue/vue-router/@vueuse/core APIs and for all components in `src/components/` (via `unplugin-auto-import` and `unplugin-vue-components`) — components and composables generally don't need explicit imports; check `auto-imports.d.ts` / `components.d.ts` if unsure whether something is auto-registered.

### Styling & icons

- UnoCSS (config in `unocss.config.ts`) is the primary styling system; supplementary hand-written CSS lives in `src/styles/` (`main.css`, `prose.css`, `markdown.css`).
- Icons are resolved through `unplugin-icons` (Iconify) with an empty component prefix, so icon components are used directly by name (see existing `.vue`/`.md` files for the naming convention in use).

### Scripts (`scripts/`)

Standalone `tsx`-run utilities invoked from `package.json` or ad hoc:
- `rss.ts` — builds `feed.xml`/`feed.atom`/`feed.json` from `pages/posts/*.md`.
- `redirects.ts` — merges `_redirects` into `_dist_redirects`, adding dynamic GitHub-repo redirects via Octokit (needs `GITHUB_TOKEN`).
- `copy-fonts.ts`, `copy-sponsors.ts` — copy static assets into the build during `pnpm build` / `pnpm static`.
- `img-compress*.ts` — image compression CLI and a staged-files variant (used by git hooks/manual runs).
- `photos-manage.ts` — manages `photos/` metadata JSON consumed by `pages/photos.md`.
- `slugify.ts` — diacritics-aware slug helper shared by the markdown anchor/TOC plugins.
- `sponsors-circles.ts` — generates the sponsor-avatar layout data consumed by `src/components/SponsorsCircles.vue`.
- `stars-rank.ts` — generates GitHub star-ranking data for display.

### Deployment

- Static output goes to `dist/`. Netlify is the deploy target: `netlify.toml` plus `_redirects` at the repo root; the build step copies the generated `_dist_redirects` to `dist/_redirects`. There's also a minimal `vercel.json`.

## Content authoring conventions

- New standalone page: add `pages/<name>.md` with YAML frontmatter (title, date, lang, tags, image, ...) — the route is generated automatically, no registration needed.
- New blog post: add `pages/posts/<name>.md`; set `lang: 'en'` to have it included in the RSS feed.
- To force a specific OG image, set `image: /path/to/image.png` in frontmatter; otherwise one is auto-generated (see OG generation above).
- Non-Markdown routes are plain `.vue` files placed directly in `pages/`.

## Ignored tooling directories

`.specify/`, `.agent/`, `.agents/`, and `.claude/` (spec-kit / agent tooling) are excluded from ESLint (see `eslint.config.js`) and are not part of the site's runtime code.
