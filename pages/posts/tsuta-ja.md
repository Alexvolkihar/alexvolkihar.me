> [English Version](/posts/tsuta) | [Version Française](/posts/tsuta-fr)

[Tsuta](https://github.com/Alexvolkihar/Tsuta)は、Swiftで書いたmacOS用のGitクライアントだ。履歴をグラフで描き、ハンクや1行単位でステージし、コンフリクトを解決し、対話的にリベースし、GitHubとGitLabのレビュー依頼を読み、リポジトリで行われたClaude CodeとCodexの会話を一覧にする。バイナリは4MB、ライセンスはMIT、アカウントは要らない。

名前は、ツタ（蔦）から取った。伸びながら枝分かれして育つ植物だ。

![Tsutaの履歴画面：コミットグラフ、選択したコミットとその差分](/images/tsuta-history.png)

## 試してみる

- ソースコード：[GitHub](https://github.com/Alexvolkihar/Tsuta)
- ビルド：

```bash
git clone https://github.com/Alexvolkihar/Tsuta.git
cd Tsuta
./scripts/build-app.sh
open build/Tsuta.app
```

必要なのはSwift 6とmacOS 14で、Xcodeがなくても、Command Line Toolsで動く。アプリは公証されていないため、初回は右クリックから「開く」を選ぶ。

## gitを置き換えず、gitを動かす

TsutaはGitを再実装していない。すべての操作は、子プロセスとしての`/usr/bin/git`の呼び出しだ。`--no-optional-locks`を付け、プロンプトは出さない。フック、設定、worktree、サブモジュールは、同じバイナリなのでターミナルと同じように動く。

実際の仕事はパースだ。`log`、`status --porcelain=v2 -z`、`diff`の出力を不変の値に変え、画面はそれを読むだけにしている。実行したコマンドはすべてコンソール（⌘J）に出る。アプリが裏で何をしているかは隠れない。

## 1行だけステージする

1行だけをステージするには、パッチを作って`git apply --cached --recount`に渡す。

パッチにはファイルのヘッダーとハンクを残し、選ばれなかった変更を無効化する。ステージするときは、選ばれていない追加行を外し、選ばれていない削除行はコンテキストに変える。その行はインデックスに残るからだ。アンステージはその鏡像で、`-R`付きで適用する。ハンクヘッダーの行数は計算し直し、`--recount`によって git はヘッダーよりも実際の行を信じる。

テストは実際のリポジトリで往復を確かめる。最初のハンクをステージし、そこから1行をアンステージし、2つ目のハンクの1行をステージし、コミットして、コミットの中身を確認する。

部分ステージには正確な差分が要る。そのため「空白の変更を隠す」がオンの間は無効になる。

## エディタを開かないリベース

gitは、タスク一覧のためにエディタを開き、rewordごとにもう一度開く。Tsutaはその両方を置き換える。`GIT_SEQUENCE_EDITOR`にはアプリが書いたtodoファイルを`cp`するコマンドを渡し、`reword`は`pick`の後ろに`exec git commit --amend -F <ファイル>`を付けた形にする。

リベースの画面は、ドラッグで並べ替える一覧だ。各行でpick、reword、squash、fixup、dropを選べる。先頭がsquashの計画は断る。まとめる先のコミットがないからだ。

## グラフ

コミットは子から親の順に届く。レイアウトは、待っているハッシュを1つずつ持つレーンの配列を保つ。コミットは、自分を待っている最初のレーンか、空いている最初のレーンに入る。最初の親は同じレーンを引き継ぎ、ほかの親には空きレーンを割り当てる。各行には、ノードに入るレーン、通り抜けるレーン、出ていくレーンを記録し、SwiftUIの`Canvas`がその間を曲線で結ぶ。

最初のマージのテストは、2本目のレーンが1本目に閉じると想定していた。アルゴリズムは正しく、間違っていたのはテストだった。マージされたブランチのレーンは曲線で親のレーンに合流し、親は元の位置にとどまる。

## フォルダを監視する

FSEventsの監視が、ターミナルやエディタで作業ツリーが変わったときに画面を更新する。gitの内部管理のファイル（オブジェクト、ログ、ロックファイル）は無視する。リポジトリを読むだけでそこに触れ、更新のループが始まってしまうからだ。連続したイベントは1回の更新にまとめる。

最初のバージョンは一度も発火しなかった。`kFSEventStreamCreateFlagUseCFTypes`がないと、コールバックにはC言語の文字列配列が渡される。私はそれを`NSArray`として読んでいた。結果は空のリストで、エラーも出なかった。

見つけられたのは、アプリが自分のウィンドウをPNGに描き出せるからだ。`Tsuta --open <リポジトリ> --snapshot out.png`と実行する。自分のビューを描くだけなので、画面収録の許可は要らない。動かしている間にファイルを作ると、一覧にそのファイルがなかった。この記事のスクリーンショットも、このコマンドで撮った。

## Claude CodeとCodex

Tsutaは2つの形でこれらを使う。

1つ目は生成だ。ステージ済みの差分からのコミットメッセージ、コミットの説明、レビューの要約、コンフリクトブロックへの提案。Tsutaは`claude`（または`codex`）を子プロセスとして起動し、標準入力にプロンプトを書く。キーもサーバーも持たない。Claudeは`-p --tools ""`で、一時ディレクトリから実行する。そのため、差分に仕込まれた指示ではファイルを読むことも変えることもできない。モデルが返せるのはテキストだけだ。差分はタグで囲み、データとしてモデルに伝える。

2つ目はAgentsタブで、リポジトリやそのworktreeで行われた会話を一覧にする。Claude Codeは、それらを`~/.claude/projects/`にJSONLファイルとして保存している。フォルダ名はパスの`/`と`.`を`-`に置き換えたものだ。Tsutaはタイトル、ブランチ、最後の活動を読み、「再開」を押すと、正しいディレクトリでTerminalが開き、`claude --resume <id>`が走る。idはファイル名から取るので、シェルのコマンドに入れる前に検証している。

## Xcodeなしで

Command Line Toolsだけで作った。そのせいで3つを失った。XCTestがなく、swift-testingのマクロがなく、プラグインがXcodeに同梱される`@State`マクロもない。テストは`tsuta-selftest`という実行ファイルになった。実際のリポジトリを作る114個の確認だ（コンフリクト付きマージ、対話的リベース、stash、worktree、部分ステージ）。画面ごとの状態は`@StateObject`で持つ。

## 制限

- アプリは公証されていない。
- GitLab（`glab`）とCodexの経路は、サンプル出力に対するパースのテストで確かめた。実際のツールに対しては実行していない。
- blameとファイル履歴はない。
- 未追跡のファイルは、丸ごとしかステージできない。
- 取り消しの対象は、コミットと破棄したファイルだ。リベースとリセットは含まない。
- Swiftで約5,200行、そのうちコアが1,400行。粗い部分は残っている。
